## 한눈에 보기

1차에 기능 7개를 더하고, 배포 전 점검은 제미나이·챗지피티 프롬프트를 그대로 쓰지 않고 조향앱에 맞게 줄인 목록으로 단계마다 나눠 확인한다. 기준은 저장소 `perfumer-lab`의 `wip/scent-studio-stage4` 브랜치(단계 4 묶음 4까지 완료)다.

- **추가할 기능 7개:** 카카오 로그인, 로그아웃, 약관·개인정보·만 14세 동의 화면, 데이터 출처·라이선스 화면, "추천이 이상해요" 신고 버튼, 첫 실행 안내(온보딩), 앱 정보
- **두 프롬프트를 그대로 넣지 않는 이유:** 이메일 가입·결제·푸시·카메라 권한처럼 조향앱에 없는 기능 검사가 절반이고, 승인 테스트 41개·서버 테스트 325개·배포 전 체크리스트 12개가 이미 있다.
- **출시를 막을 수 있는 것:** Play 비공개 테스트 의무(12명, 14일), targetSdk 36, 구글 로그인 운영 전환, Fragrantica 회신

**사장 결정**

남은 결정은 없다. 아래대로 진행하고, 다음 세션에서 프롬프트 A부터 넣는다.

**정한 것 (2026-11-08)**

- **기능 7개를 1차에 넣는다.** 카카오 로그인, 로그아웃, 동의 화면, 출처·라이선스 화면, 신고 버튼, 온보딩, 앱 정보. 카카오 로그인과 동의 화면은 묶음 8·9 전에 계획에 넣는다.
- **Play는 바로 공개하지 않고 비공개 테스트를 거친다.** 테스터 12명 이상(넉넉히 15명)이 14일 동안 쓰고, 이 기간을 주변인 테스트·수정 기간으로 쓴다. 예전 결정 "초대제 테스트 없이 공개(2026-11-06)"을 대체한다.
- **화면은 세로 고정.** `app.json`의 `"orientation": "default"`를 `"portrait"`로 바꾼다. PC 넓은 화면 배치(왼쪽 메뉴, 목록·상세 나란히)는 그대로다.

## 1차에 추가할 기능

7개 모두 지금 기능표(spec 1\~11번)에 없거나, 서버는 계획됐는데 화면이 빠져 있다. 카카오 로그인과 동의 화면은 서버와 레드팀 범위에 영향을 주니 묶음 8·9 전에 정하고, 나머지는 화면 단계(단계 5)에서 넣는다.

| 기능 | 왜 필요한가 | 어디에 | 언제 넣나 |
| --- | --- | --- | --- |
| 카카오 로그인 | 대상이 20\~30대 한국 사용자. Supabase가 카카오를 기본 지원해 서버 변경이 적다 | S12 로그인 | 묶음 8 전 결정, 화면은 단계 5 |
| 로그아웃 | 기능표에 계정 삭제만 있고 로그아웃이 없다 | S11 마이 | 단계 5 |
| 약관·개인정보·만 14세 동의 화면 | 서버 동의 저장(묶음 4)은 있는데 처음 로그인할 때 보여 줄 화면이 없다. 실제 문구 작성 후 `draft-1` → 날짜 버전 | 로그인 직후 | 문구는 묶음 9 전, 화면은 단계 5 |
| 데이터 출처·라이선스 화면 | Decant 데이터(CC BY-NC-SA 4.0)는 출처 표시 의무. Parfumo·Fragrantica·Decant 출처와 오픈소스 라이선스를 한 페이지에 | S11 마이 | 단계 5 |
| "추천이 이상해요" 신고 버튼 | 서버 오류 신고(묶음 7)는 계획됐는데 누를 화면이 없다 | S07 향수 상세 | 묶음 7 + 단계 5 |
| 첫 실행 안내(온보딩) | 향수 입문자에게 "탑·미들·베이스", "어코드"가 낯설다. 2\~3장, 건너뛰기 가능 | 첫 실행 | 단계 5 |
| 앱 정보(버전·문의 메일) | Play가 문의 메일을 요구하니 앱에도 같이 둔다 | S11 마이 | 단계 5 |

**카카오 로그인을 넣으면 같이 정할 것**

- **이메일을 못 받을 수 있다.** 카카오의 이메일 동의 항목은 "비즈 앱"에서만 쓸 수 있다. 비즈 앱이 아니면 Supabase에서 "이메일 없는 사용자 허용"을 켜고, 서버 `GET /me`가 이메일 없이도 동작하는지 테스트를 더한다. ([Supabase 문서](https://supabase.com/docs/guides/auth/social-sign-in/auth-kakao))
- **계정이 두 개로 나뉜다.** 같은 사람이 구글과 카카오로 각각 가입하면 보관함이 따로다. 1차는 "다른 방법으로 로그인하면 보관함이 따로예요" 안내만 두고 계정 합치기는 나중에.
- **로그인 파일을 고치니 `.redteam-needed`가 생긴다.** 묶음 9 레드팀 범위에 카카오 토큰도 넣는다.

## 나중에 할 것 / 안 넣을 것

이메일 직접 가입은 넣지 않는다. 비밀번호 찾기·인증 메일·비밀번호 보안과 그 테스트가 전부 따라오고, 이미 "구글만, 이메일 가입은 끄기"로 정했다. 로드맵 2\~5차에 이미 있는 기능(향수 비교, SNS 공유 카드, 계절 필터 등)은 다시 적지 않는다.

| 기능 | 판단 | 이유 |
| --- | --- | --- |
| 애플 로그인 | 앱스토어 낼 때 | spec에 "앱스토어 땐 애플 로그인 필수"로 적혀 있고, 로그인 방법을 더할 수 있는 구조다 |
| 향수 찾기 계열·브랜드 필터 | 1차 끝나고 | 지금은 이름·브랜드 검색만 있다 |
| 최근 본 향수 | 나중 | 기기 저장만으로 돼서 서버 작업이 없다 |
| 조합 링크 공유(카톡) | 2차 | 공유 카드(5차)보다 작게 시작할 수 있다. 딥링크 작업이 생긴다 |
| 이메일 직접 가입 | 안 함 | 위 문단 |
| 네이버 로그인 | 안 함(당분간) | Supabase 기본 지원이 아니어서 직접 붙여야 한다. 카카오+구글이면 대부분 커버된다 |
| 향수 구매 링크 | 안 함 | 비상업 운영 조건, spec의 "외부 구매 링크 없음"과 충돌 |
| 리뷰·커뮤니티 | 안 함(5차) | 신고·관리 책임과 Play 정책 검사가 늘어난다 |
| 푸시 알림 | 안 함 | 보낼 내용이 없고 권한·테스트만 늘어난다 |

## Claude Code에 물어볼 타이밍

두 프롬프트를 통째로 넣지 않고, 아래 여섯 번에 나눠 짧게 물어본다. 작업장 규칙대로 기능 추가는 `/build-app` 순서를 따른다.

1. **지금, 묶음 5 시작 전** — 기능 7개 추가 + 점검 항목을 계획에 넣기 (프롬프트 A)
2. **묶음 9 레드팀 끝난 뒤, 배포 승인 전** — 서버 운영 설정 점검 (B)
3. **단계 5 화면 완성 후, 6단계 전** — 화면·예외 상황 점검 (C)
4. **6단계 QA 보고 때** — 보고 형식 지정 (D)
5. **EAS 운영 빌드 후, Play 제출 전** — 릴리스 빌드·스토어 점검 (E)
6. **공개 직후** — 스모크 테스트 (F)

## 배포 전 주변인 테스트와 수정

Play 비공개 테스트(12명, 14일)를 어차피 해야 하면, 그 기간을 주변인 테스트 기간으로 쓴다. 위 타이밍으로는 4번(6단계 QA)과 5번(Play 제출 전 최종 점검) 사이다.

일정: 화면 완성(단계 5) → 6단계 QA → **비공개 테스트 14일(주변인 테스트 + 수정)** → 마지막 빌드로 최종 점검(프롬프트 C·E) → 공개

1. **나눠주기:** 안드로이드는 Play 비공개 테스트로 초대(Play 스토어에서 설치), 아이폰 사용자는 웹 주소로.
2. **의견 모으기:** 구글 폼 하나 + 앱 안 "추천이 이상해요" 버튼.
3. **분류하기:** 버그(안 됨·멈춤·글자 잘림)는 바로, 불편함(버튼 위치·문구·안내)은 작으면 바로, 새 기능은 크면 1차 이후로.
4. **고친 버전 다시 올리기:** 비공개 테스트 중에도 새 빌드를 올리면 테스터가 업데이트로 받는다. 웹은 다시 올리면 바로 바뀐다.
5. **끝나면 최종 점검:** 마지막 빌드로 프롬프트 C·E를 한 번 더 돌리고 공개.

**지킬 것**

- 1차에 넣는 기준은 "있으면 좋겠다"가 아니라 **"이게 없어서 못 쓰겠다"**. 다 넣으면 출시가 계속 밀린다.
- 새 기능은 `/build-app` 순서로 넣고, 로그인·계정을 건드리면 레드팀을 다시 돌린다.
- 테스터가 14일 동안 빠지면 12명이 안 채워질 수 있다. 12명보다 몇 명 더 초대한다.
