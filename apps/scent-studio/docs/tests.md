# scent-studio 테스트 목록 (1차)

> 작성: QA팀 · 2026-10-30 · /build-app 3단계 결과물
> **사장 승인: 2026-10-30 승인 (40개). 2026-10-31 재승인 (41개)**: 설계가 E안(Expo, 웹·안드로이드·아이폰 공통)으로 바뀌어 확인 방법과 A1·A7·C2·E1·H1·H3·H4의 표현을 고치고 H5를 더했다. 검사 내용과 숫자는 그대로다. 승인 대상은 이 문서의 "승인 목록" 하나뿐이다. 사장 허락 없이 고치거나 지우지 않는다.
> 이 목록이 모두 통과해야 1차가 "끝"이다.

## 어떻게 확인하나
- PC에서 자동으로 돌린다. 앱을 웹으로 내보내 **실제 크롬 브라우저**에서 사람처럼 누르고 글자를 읽어서 확인한다(Playwright). 폰 크기와 PC 크기 화면 둘 다 본다. 폰 앱 자체는 6단계에 따로 확인한다.
- **가짜 향수 데이터**(약 60개, 테스트용으로 직접 만든 것)와 **가짜 서버**를 쓴다. 그래서 결과가 매번 똑같고 인터넷이 없어도 돈다.
- 구글 로그인은 자동으로 누를 수 없어서, 테스트에서는 "로그인된 상태"를 흉내 낸다. 진짜 구글 로그인은 6단계에 사장이 실제 폰으로 확인한다(맨 아래 "사장 직접 확인").
- 아래에 나오는 노트·향수 이름은 가짜 데이터에 넣어 둘 예시다.

## 승인 목록

### A. 향 조합 만들기
| # | 이렇게 하면 | 이렇게 되어야 한다 |
|---|---|---|
| A1 | 앱을 켠다 | 폰 크기에서는 하단 탭 4개(홈 · 향수 찾기 · 보관함 · 마이), PC 크기에서는 왼쪽 메뉴에 같은 4개가 보이고, 홈에 "새 조합 만들기"가 있다 |
| A2 | 새 조합 → 계열 "시트러스", "우디" 선택 → 다음 | 노트 선택 화면에 탑 · 미들 · 베이스 층 탭이 있고, 고른 계열의 노트가 먼저 보인다 |
| A3 | 탑에 레몬(강), 미들에 장미(중), 베이스에 샌달우드(약)를 고른다 | 노트마다 고른 강도가 표시된다 |
| A4 | 탑에 노트 3개를 고른 뒤 4번째를 누른다 | 4번째는 들어가지 않고 "층마다 3개까지 고를 수 있어요"가 보인다 |
| A5 | 검색창에 "베르가"를 친다 / "berg"를 친다 | 둘 다 "베르가못"이 나온다 |
| A6 | 목록에는 없는 드문 노트(검색 전용) 이름을 검색한다 | 검색 결과에 나오고 고를 수 있다 |
| A7 | 노트의 정보 버튼을 누른다 (**목록의 모든 노트**에서) | 노트 카드(폰 크기: 아래에서 올라옴, PC 크기: 옆 패널)에 한 줄 설명, 계열, 잘 어울리는 노트 **3개**가 보인다. 실제로 함께 쓰인 노트가 3개보다 적으면(0개 포함) 같은 계열에서 많이 쓰는 노트로 채우고, 채운 노트에는 "같은 계열 추천"이 작게 보인다 (2026-11-12 사장 수정 허락) |
| A8 | A3 상태에서 "조합 요약"으로 간다 | 층별로 고른 노트가 보이고, 어코드 막대마다 이름과 %가 글자로 보이며, %를 더하면 100이다 |
| A9 | 베이스를 비운 채 요약으로 간다 | "베이스가 비어 있어 잔향이 가볍게 느껴질 수 있어요" 같은 안내가 보인다 |
| A10 | 요약에서 "노트 수정"을 누른다 | 노트 선택 화면으로 돌아가고, 고른 노트가 그대로 있다 |

### B. 추천 보기
| # | 이렇게 하면 | 이렇게 되어야 한다 |
|---|---|---|
| B1 | 요약에서 "추천 보기"를 누른다 | 향수 10개가 점수 높은 순서로 나온다 |
| B2 | 추천 목록을 본다 | 향수마다 브랜드·이름, 점수와 등급(매우 비슷 / 비슷 / 참고), 공통 어코드, 일치한 노트가 보인다 |
| B3 | 한 브랜드 향수가 많은 가짜 데이터로 추천을 본다 | 10개 안에 같은 브랜드는 최대 2개다 |
| B4 | 기획서의 맹점 조합(레몬 강 + 오스만투스 중 + 샌달우드 약)으로 추천을 본다 | 1위가 가짜 데이터에 넣어 둔 "가벼운 시트러스·플로럴 향수"이고, "무거운 우디 향수"는 그보다 아래다 |
| B5 | 추천 1위를 누른다 | 향수 상세에 노트 피라미드(탑·미들·베이스), "내 조합 vs 이 향수" 어코드 비교 막대(이름과 %), 일치한 노트와 이 향수에만 있는 노트가 보인다 |
| B6 | 추천 화면과 향수 상세를 본다 | "데이터상 유사도"라는 말과 데이터 출처(Parfumo)가 보인다 |

| C3 | 마이에서 선호 계열 "플로럴"을 정하고 같은 조합으로 추천을 본다 | 순위가 바뀌어, 플로럴 어코드가 강한 향수가 전보다 위로 온다 |

### D. 저장 · 찜 · 시향 피드백
| # | 이렇게 하면 | 이렇게 되어야 한다 |
|---|---|---|
| D1 | 로그인하지 않고 조합 "저장"이나 향수 "찜"을 누른다 | 로그인 화면이 나온다 |
| D2 | 로그인한 상태로 조합에 이름을 붙여 저장한다 | 보관함 "조합"에 그 이름으로 보인다 |
| D3 | 로그인한 상태로 향수를 찜한다 / 다시 눌러 찜을 푼다 | 보관함 "찜"에 생겼다가 사라진다 |
| D4 | 향수 상세에서 시향 피드백(만족도 4, 비슷했나 3, 메모)을 남긴다 | 보관함 "시향 기록"에 점수와 메모가 보인다 |

|---|---|---|
| L1 | 기기 4종에서 앱을 켠다 | 빨간 오류 화면·크래시 없이 홈까지 열린다 |
| L2 | 4종에서 홈 · 노트 선택 · 요약 · 추천 · 상세 · 보관함 · 마이를 연다 | 노치·아일랜드·홈 바·안드로이드 내비게이션 바에 글자·버튼·탭이 가리지 않는다 |
| L3 | 노트 검색 · 향수 찾기에 한글("베르가못")을 친다 | 키보드가 입력창을 가리지 않고, 글자를 조합하는 중에도 깨지지 않으며 결과가 나온다 |
| L4 | 안드로이드 뒤로 버튼 · iOS 스와이프로 상세 → 추천 → 요약 순서로 돌아간다 | 한 단계씩 돌아가고, 열린 창은 먼저 닫히고, 고른 노트가 그대로다 |
| L5 | 시스템 다크 모드 · 글자 크기 200%로 L2의 화면을 연다 | 글자가 보이고, 잘림·겹침 없이 스크롤로 다 볼 수 있다 |
| L6 | 폰을 가로로 돌린다 | 세로 그대로다(개발용 빌드로 확인) |
| L7 | 비행기 모드로 새 조합 → 추천을 하고, 서버가 잠든 상태에서 로그인 후 저장한다 | 추천은 되고, 저장은 "서버를 깨우는 중이에요" → 저장 완료 또는 "다시 시도"가 나온다 |
| L8 | 앱을 처음 연 화면을 본다 | 글꼴이 네모(□)로 나오거나 크게 깜빡이지 않는다 |
| L9 | 작은 안드로이드(360dp급)에서 앱을 처음 실행한다(받아 둔 카탈로그 없음) | 카탈로그 첫 로딩이 **2초 이내**다. 넘으면 대책(미리 만든 인덱스, 나눠 읽기, 백그라운드 처리 등)을 제안하고 멈춘다. 측정 방법은 다음 세션에 정한다 |

**L9 측정 기록**
| 날짜 | 기기 | 빌드 | 값(ms) | 판정 |
|---|---|---|---|---|
| 2026-11-12 | 갤럭시 S26 울트라(큰·빠른 폰) | Expo Go(개발 모드) | 1556 / 1428 / 1420 (open 약 1,400 · engine 67) | **큰 폰 참고값** — L9 기준 기기(작은 안드로이드 360dp급)가 아니라 판정 아님 |

- 정식 판정: 5-9 **릴리스 빌드**, 작은 안드로이드(실기기 또는 에뮬레이터 ① 2코어·2GB), 5회 중앙값(`docs/device_setup.md` 4절).

## 사장 직접 확인 (6단계, 실제 폰)
자동 테스트로는 못 하는 것이다. 6단계 QA 보고 때 확인 방법을 함께 드린다.
1. 진짜 구글 계정으로 로그인(안드로이드 앱과 웹 둘 다) → 저장·찜·피드백 → 앱을 지웠다 다시 깔아도 보관함이 그대로
2. 실제 서버(배포된 주소)에서 저장이 된다
3. 계정 삭제 후 같은 구글 계정으로 다시 로그인하면 빈 보관함
4. 화면 느낌이 디자인 규칙(고급스럽고 깔끔하게)과 맞는다
5. 아이폰 사파리에서 웹 주소를 열고 "홈 화면에 추가" → 아이콘으로 열어 새 조합 → 추천이 된다
6. (2026-11-09 추가) 진짜 카카오 계정으로 로그인(안드로이드 앱과 웹) → 동의 → 저장. 같은 사람이 구글로 로그인하면 보관함이 따로인지
7. (2026-11-09 추가) 안드로이드 앱이 세로로 고정되어 폰을 돌려도 가로로 바뀌지 않는다

## 참고: QA팀이 따로 더하는 테스트 (승인 대상 아님)
- **추천 계산(엔진):** Python 참조 엔진과 TypeScript 엔진의 결과가 같은지(가짜 데이터 기대 결과와 순위가 같고 점수 차가 1e-9 이하). 비율 합 100, 불호 노트 제외, 같은 입력 같은 결과
- **서버:** 로그인 없으면 거절, 남의 조합을 읽거나 지울 수 없음, 잘못된 입력 거절, 계정 삭제 후 데이터 없음
- **앱 부품:** 층당 3개 제한, 임시 저장 복원, 설정 합치기, 기록 대기열(최대 1,000개)
- **화면 캡처(Playwright):** 화면마다 라이트·다크 × 작은 폰·큰 폰·PC + 글자 200%. 디자인 검토 시안으로도 쓴다
- **폰 앱 확인:** EAS로 만든 안드로이드 설치 파일로 새 조합 → 추천 → 상세, 앱 재시작 후 이어 하기, 비행기 모드에서 추천. 6단계 보고 전에 돌린다
- **엔진 품질(실제 데이터):** 설계서 14절 합격 기준표(재현, 맹점, 블라인드 비교, 눈으로 평가, 다양성). 백엔드팀 사장 검토 때 결과를 보여 드린다
