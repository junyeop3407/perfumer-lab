## 목표
사용자가 탑·미들·베이스 노트를 직접 골라 "나만의 향"을 조합하면, 실제 판매 향수 중
**전체 분위기(어코드 비중)가 가장 비슷한** 제품을 유사도 순으로 추천한다.
추천은 점수만 보여 주지 않고 "왜 비슷한지"(어코드 비율 비교, 일치한 노트)를 함께 보여 준다.

## 사용자
- 향수를 좋아하지만 노트·향 계열을 잘 모르는 입문자 (20~30대)
- 쓰는 곳: **안드로이드 폰, 아이폰, PC 브라우저** (2026-10-31 사장 결정. 그 전 10-30에는 안드로이드 전용이었음)
- 플랫폼 (2026-10-31):
  - **웹**: 하나의 웹 주소로 폰·PC 어디서나 연다. 폰에서는 "홈 화면에 추가"로 앱처럼 쓴다. PC에서는 넓은 화면에 맞게 배치를 바꾼다(폰 화면을 가운데 띄우기만 하지 않음)
  - **안드로이드**: 같은 화면을 앱으로 포장해 Play **내부 테스트**로도 배포한다
  - **아이폰**: 1차는 웹 주소(사파리 "홈 화면에 추가")로 쓴다. **앱스토어 배포는 다음 차수**지만, 그때 다시 만들지 않도록 1차부터 앱스토어 규칙에 막히지 않게 만든다(아래 "앱스토어 대비")

## 핵심 개념 (모든 팀 공통 용어)
| 용어 | 뜻 |
|---|---|
| 노트 | 향을 이루는 개별 재료 이름 (레몬, 장미, 샌달우드 …) |
| 층 | 탑(처음) · 미들(중심) · 베이스(잔향). 노트마다 사용자가 층을 정해 고른다 |
| 계열 | 노트를 묶는 큰 분류 (시트러스, 플로럴, 우디 …) |
| 어코드 | 향수 전체의 분위기 테마와 그 비율 (예: 시트러스 60 · 플로럴 30 · 우디 10) |
| 강도 | 사용자가 노트마다 고르는 세기: 약 0.5 / 중 1.0 / 강 1.5 |
| 불호 노트 | 사용자가 싫다고 표시한 노트. 이 노트가 든 향수는 추천에서 아예 뺀다 |

## 추천 규칙 (가장 중요한 결정)
**어코드 비중과 노트 일치를 같은 무게로 쓴다** (2026-10-30 변경. 처음엔 "어코드 메인, 노트 보조").
노트 하나하나가 아니라 전체 분위기를 비교하는 어코드는 맹점을 막고, 노트 일치는 내가 고른 재료가 든 향수를 찾아 준다.
- 이유: 노트 포함 여부만 보면 "레몬 + 오스만투스 + 샌달우드"를 고른 사람에게, 세 노트가 다 들었지만
  샌달우드가 지배하는 묵직한 우디 향수가 1순위로 나온다. 어코드 비중으로 비교하면 가벼운 조합에는
  가벼운 향수가 나온다.
- 점수 = 어코드 비중 유사도 45% + 단계별 노트 일치도 45% + 개인 취향 10%
  (취향 정보가 없는 사용자는 어코드:노트를 1:1로 100%를 만든다)
  - 2026-10-30 변경: 처음엔 60/30/10이었다. 실제 데이터로 시험하니 고른 노트가 다 든 향수도 잘 못 찾아서(재현 9/20) 45/45/10으로 바꿨다(15/20). 무거운 향수가 위로 오는 맹점은 여전히 막힌다(5/5)
- 불호 노트는 점수가 아니라 **후보 제외 필터**다.
- 정확한 계산식과 순서는 `design.md` "추천 엔진 명세"를 따른다. 가중치는 시작값이며 시향 피드백으로 조정한다.

## 기능 우선순위
### 1차 (MVP, 이번에 만든다)
| 순위 | 기능 | 설명 |
|---|---|---|
| 1 | 노트 선택 | 계열 선택(복수) → 탑·미들·베이스 층별로 노트 1~3개, 노트 검색(한글·영문), 노트별 강도. 목록에는 자주 쓰이는 노트(약 540종)만, 나머지는 검색으로 |
| 2 | 노트 카드 | 한 줄 설명, 계열, 자주 함께 쓰이는 노트 3개(궁합 힌트) |
| 3 | 조합 요약 | 층별 노트 정리, 조합의 어코드 비율 막대, 균형 안내(빈 층, 한 계열만, 한 어코드가 너무 강함, 대비가 큼) |
| 4 | 유사 향수 추천 | Top 10: 유사도 점수와 등급(매우 비슷 / 비슷 / 참고), 공통 어코드, 일치한 노트. 한 브랜드는 최대 2개. **폰·브라우저 안에서 계산해, 한 번 연 뒤에는 인터넷 없이도 된다** |
| 5 | 향수 상세 | 노트 피라미드, 내 조합 vs 향수 어코드 비율 비교 막대, 일치·차이 노트 |
| 6 | 불호 노트 필터 | 마이에서 설정, 추천에 자동 적용. 로그인 없이도 기기(폰·브라우저)에 저장해 바로 적용하고, 로그인하면 서버 값과 합친다 |
| 7 | 저장 | 조합 저장, 향수 찜 (로그인 필요) |
| 8 | 시향 피드백 | 만족도 1~5, "조합과 비슷했나" 1~5, 메모 (로그인 필요) |
| 9 | 로그인 | 구글 로그인 1종. 비로그인도 조합·추천까지는 사용 가능. 로그인 방법을 나중에 더할 수 있게 만든다(앱스토어 때 애플 로그인) |
| 10 | 계정 삭제 | 마이에서 계정과 내 데이터를 모두 삭제 (Play·앱스토어 정책 필수). 웹에서 삭제를 요청하는 방법도 안내 페이지로 제공 |
| 11 | 사용 기록 | 화면 없음. 성공 기준을 재기 위한 최소한의 기록(조합 시작·완료, 추천 보기, 저장 등). 광고 ID는 쓰지 않음 |

### 앱스토어 대비 (1차부터 지킬 것, 2026-10-31)
나중에 아이폰 앱스토어에 올릴 때 다시 만들지 않도록 1차부터 이렇게 만든다.
- 화면은 하나로 만들어 웹·안드로이드 앱·아이폰 앱이 같이 쓴다. 아이폰 앱도 같은 화면을 포장해서 만든다
- 로그인은 방법을 더할 수 있는 구조로 만든다. 앱스토어는 구글 로그인을 주면 **애플 로그인도 함께** 주도록 요구한다
- 계정 삭제를 앱 안에 둔다(애플도 필수)
- 앱 안에서 다른 곳 결제·외부 구매 링크를 두지 않는다(1차에 원래 없음)
- 웹 주소만 감싼 "껍데기 앱"은 애플 심사에서 거절되기 쉬우므로, 화면과 데이터를 앱 안에 넣어 인터넷 없이도 핵심 기능(조합 → 추천)이 되게 한다(기능 4)
- 개인정보처리방침 페이지와 "어떤 데이터를 모으는지"를 정리해 둔다(사용 기록, 광고 ID 안 씀)

### 다음 차수 후보 (이번에는 만들지 않는다, 순서대로)
- 아이폰 앱스토어 배포 (애플 개발자 계정·애플 로그인 추가 필요. 맥 컴퓨터 또는 클라우드 빌드 서비스가 필요)
- 2차: 기존 향수 변형(좋아하는 향수를 불러와 노트 더하고 빼기), 대체 향수 찾기, 계절·TPO 태그와 필터, 향 전개 미리보기(탑→미들→베이스 키워드)
- 3차: 향수 2~3개 비교, 지속력·발향력·가격대 필터(데이터가 있을 때만), LLM이 쓰는 추천 이유 문장
- 4차: 마이 향기 리포트(선호 어코드 방사형 그래프), 피드백으로 개인별 가중치 조정
- 5차: 레시피 공유 커뮤니티, SNS 공유 카드, 레이어링 추천(실험)

## 하지 않을 것 (1차)
- 가격·구매 링크·재고 표시 (공개 데이터에 가격이 거의 없음)
- 지속력·발향력 필터, 향수 비교, 커뮤니티, 레이어링
- 브랜드 공식 향수 이미지 사용 (저작권). 향수 카드는 브랜드·이름과 상위 어코드(글자)로 표시
- "실제 향이 같다"는 식의 표현. 화면에는 "데이터상 유사도"라고 쓴다
- 사용자가 데이터를 직접 입력·수정하는 기능 (카탈로그는 읽기 전용)
- 아이폰 **앱스토어** 배포 (1차는 웹 주소로 사용. 다음 차수 후보 맨 앞)
- Play 스토어 정식 공개. 1차는 **Play 내부 테스트(초대한 사람만)**까지. 정식 공개는 데이터 라이선스를 확인한 뒤 정한다

## 성공 기준 (베타 10명 기준으로 측정, 사용 기록으로 계산 — `design.md` 13절)
- 조합 완성률: 조합 시작 → 추천 결과 도달 비율
- 추천 저장률, 시향 피드백률
- "조합과 비슷했나" 평균 점수
- 재방문율

## 검증할 가설
1. 어코드 중심 추천이 노트 일치 중심 추천보다 "조합과 비슷했다" 점수가 높다
2. 어코드 비율 막대와 일치 노트를 함께 보여 주면 추천을 더 믿는다
3. 시향 피드백이 다음 추천 만족도를 높인다
