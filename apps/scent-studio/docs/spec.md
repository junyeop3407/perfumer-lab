# scent-studio 명세서 (Claude 작업 기준, 늘 지금 상태)

> 사장 검토용이 아니라 Claude가 앱 전체를 파악하려고 쓰는 문서다. 기준 문서는 `requirements.md`(기획)·`design.md`(설계)이고, 이 문서는 그 둘의 현재 결론을 한곳에 모은다. 다르면 사장이 마지막에 정한 쪽에 맞춘다.
> 마지막 갱신: 2026-10-31 (4단계 단계 1·2: Expo 뼈대, 승인 테스트, TS 엔진)

## 한 줄 설명
(앱 이름 Perfumer-LAB) 탑·미들·베이스 노트를 골라 "나만의 향"을 조합하면, 실제 향수 중 어코드 비중과 노트 일치가 가장 비슷한 것을 이유와 함께 추천한다.

## 누가, 어디서
- 향수 입문자(20~30대). 한국어 화면.
- 웹 주소 하나로 폰(안드로이드·아이폰)·PC 브라우저에서 쓴다. 폰은 "홈 화면에 추가".
- 안드로이드는 같은 화면을 앱으로 포장해 Play 내부 테스트(초대한 사람만)로도 배포.
- 아이폰 앱스토어는 다음 차수. 1차부터 막히지 않게(아래 "앱스토어 대비").
- PC 넓은 화면: 하단 탭 → 왼쪽 메뉴, 목록·상세 나란히, 노트 카드는 옆 패널.

## 기능 (1차)
| # | 기능 | 화면 | 동작 | 예외 상황 |
|---|---|---|---|---|
| 1 | 노트 선택 | S02 계열 → S03 노트 | 계열 여러 개 → 층(탑·미들·베이스)마다 노트 1~3개, 한글·영문 검색, 노트별 강도(약·중·강) | 층당 4번째 노트는 안 들어감, 같은 노트 두 번 불가, 검색 결과 없음 문구, 목록엔 약 540종·나머지는 검색으로만 |
| 2 | 노트 카드 | S04 (폰: 아래 시트, PC: 옆 패널) | 한 줄 설명, 계열, 궁합 노트 3개 | 설명 없는 노트는 계열 공통 문구 |
| 3 | 조합 요약 | S05 | 층별 노트, 어코드 비율 막대(합 100%), 균형 안내 4종(8-7절) | 노트 0개면 추천 버튼 비활성 |
| 4 | 유사 향수 추천 | S06 | Top 10, 점수·등급(매우 비슷/비슷/참고), 공통 어코드, 일치 노트, 브랜드 최대 2개, 같은 향수 다른 농도는 1개 | **기기 안에서 계산**, 한 번 연 뒤 인터넷 없이 됨. 후보가 10개 미만이면 있는 만큼 |
| 5 | 향수 상세 | S07 | 노트 피라미드, 내 조합 vs 향수 어코드 비교 막대, 일치·차이 노트 | 향수 찾기(S08)에서도 진입 |
| 6 | 불호 노트 필터 | S11 마이 | 불호 노트가 든 향수는 후보에서 제외 | 로그인 전엔 기기에 저장해 바로 적용, 로그인하면 서버와 합침(불호 합집합, 선호는 서버에 없을 때만 기기 값) |
| 7 | 저장·찜 | S05, S07 → S09 | 조합 저장, 향수 찜 | 로그인 필요 → 로그인 화면(S12)으로. 인터넷 없으면 오류 + 다시 시도, 몰래 쌓지 않음 |
| 8 | 시향 피드백 | S10 | 만족도 1~5, 비슷했나 1~5, 메모 500자 | 로그인 필요 |
| 9 | 로그인 | S12 | 구글 1종. 로그인 방법을 더할 수 있는 구조 | 비로그인도 조합·추천 가능 |
| 10 | 계정 삭제 | S11 | 계정·내 데이터 전부 삭제 | 웹 삭제 요청 안내 페이지도 |
| 11 | 사용 기록 | 화면 없음 | design.md 13절 이벤트 7종, install_id만(광고 ID 안 씀) | 인터넷 없으면 나중에 전송, 최대 1,000개 |
| — | 만들던 조합 이어 하기 | S01 홈 | 조합 흐름 중 바뀔 때마다 기기에 임시 저장 | 앱·브라우저를 껐다 켜도 남음 |

하단 탭 4개: 홈 · 향수 찾기 · 보관함 · 마이. 새 조합 흐름(S02→S07)은 홈에서 시작하는 전체 화면.

## 추천 엔진 (요약, 정확한 식은 design.md 8절)
- 점수 = 0.45·어코드 코사인 + 0.45·노트 일치 + 0.1·선호 계열 (선호 없으면 앞 둘을 0.9로 나눔). engine_version 2.
- 노트 프로필 = 평균 초과분 + 데이터 적은 노트는 계열 평균으로 끌어당김(K=20).
- 강도 약 0.5 / 중 1.0 / 강 1.5 — **"강" 값과 프로필 방식은 재검토 중**(아래 아직 안 정한 것).
- 기준 구현은 Python 참조 엔진 `pipeline/engine_ref.py`, 골든 파일 `tests/golden/recommend_cases.json`. 앱 엔진은 TypeScript `app/src/engine/`(Vitest 골든 통과, 2026-10-31). Java 엔진은 지웠다.

## 데이터 구조
- 카탈로그(읽기 전용, 파일 하나 `catalog.json.gz` 약 1MB): 버전, 계열 10, 어코드 21, 노트(key, 한글명, 계열, 공개 범위, 프로필, 궁합), 향수(key, 브랜드, 이름, group, 층별 노트, 어코드 벡터, 평가 수), 출처 문구. 원본·실제 카탈로그는 커밋 안 함.
- 서버 DB(Postgres `app` 스키마, RLS로 공개 API 차단): user_preferences, blends(notes jsonb: note_key·layer·intensity), favorites, tasting_feedback(그때 순위·점수·엔진·카탈로그 버전 포함), events. 사용자 id는 토큰에서만.
- 삭제: 계정 삭제는 한 트랜잭션으로 사용자 행 전부 삭제, events의 user_id는 null.
- 조합 검증: 층당 ≤3, 전체 ≥1, 노트 중복 없음, 강도 ∈ 허용값, 노트 key는 현재 카탈로그에 있는 것, 이름 ≤40자, 메모 ≤500자.

## 앱스토어 대비 (1차부터)
- 화면 코드 하나를 웹·안드로이드·아이폰이 함께 쓴다.
- 로그인 방법 추가 가능한 구조(앱스토어 땐 애플 로그인 필수).
- 앱 안 계정 삭제. 외부 결제·구매 링크 없음.
- 화면과 카탈로그를 앱 안에 넣어 오프라인으로 핵심 기능이 됨("껍데기 앱" 거절 회피).
- 개인정보처리방침 페이지, 수집 데이터 목록 정리.
