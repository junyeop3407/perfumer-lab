사용자에게 남은 질문: 디자인 방향 — ① 깔끔한 흰색 + 파란 포인트(추천) ② 따뜻한 베이지·향수 매장 느낌 ③ 어두운 고급 느낌
다음 할 일: 아래 "3단계 시작 전 확인"부터

## 지금까지 한 것
- 1단계(기획)와 2단계(설계)는 사장과 Claude 앱 대화에서 진행했다. 결과물이 이 폴더에 있다:
  - `docs/requirements.md` — 기획서 (목표, 사용자, 기능 우선순위, 하지 않을 것, 화면 흐름도)
  - `docs/design.md` — 고른 안(A안: React + Spring, 데이터 작업만 Python)과 버린 안, 추천 엔진 명세, API, 테스트 설계, 구현 순서
  - `docs/reference.md` — 배경 자료 (데이터 소스 목록과 주의점, 노트 정규화 사례, 조향 기초, 참고 사이트). 기준 문서가 아니라 참고용
- 기준은 requirements.md와 design.md 두 문서다. 저장소 밖 문서(Claude 앱의 설계 문서 등)와 다르면 이 폴더의 문서를 따른다.
- 이 앱의 1·2단계를 다시 묻지 않는다. 설계안 3개도 다시 만들지 않는다.

## 3단계 시작 전 확인 (사장에게 짧게, 한 번에 하나씩)
1. 기획서·설계서를 5줄로 요약해 보여 주고 "1·2단계 결과로 OK인지" 확인받는다. 고칠 점이 있으면 문서를 고치고 다시 확인받는다.
2. 디자인 방향(위 남은 질문)을 보기 + 추천으로 묻고, 고른 것을 `docs/design.md` 3절에 적는다.
3. 그다음 QA팀이 `docs/design.md` 9절을 재료로 테스트 목록(`docs/tests.md`)을 쉬운 말로 써서 승인받는다.

## 메모
- 테스트 명령 줄은 아직 없다. 3단계에서 테스트를 만들 때 `bash tests/run.sh`로 추가한다(그 전까지 훅이 이 앱을 건너뛴다).
- 4단계 구현 순서는 `docs/design.md` 10절. 추천 엔진은 화면보다 먼저 노트북으로 검증하고, 합격 기준표를 백엔드팀 사장 검토 때 보여 준다.
- 원본 데이터 CSV는 커밋하지 않는다 (`pipeline/data/raw/`).
